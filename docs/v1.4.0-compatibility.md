# Discord 2.0 v1.4.0 — compatibility

Which desktop versions work with which server, and which features need the upgraded backend.
Companion to the [release-readiness report](v1.4.0-release-readiness.md) and the
[deployment and rollback plan](v1.4.0-deployment-and-rollback.md).

- **Today's production server:** commit `86831b4` (Milestone 11), **API 4**.
- **v1.4.0 server:** Milestones 13 and 14, **API 6**. Desktop apps detect what a server supports:
  - flags in `GET /api/meta` (`customization`, `savedMessages`, `userNotes`, `gifs`, `largeFiles`,
    `registration`, `emailAccounts`, `email`);
  - fields that only API 6 sends (for example a server's `defaultNotifications` or a voice
    channel's `userLimit`);
  - the `moderateMembers` permission bit.

  A feature the server doesn't support is hidden or kept on the PC; it never calls a missing
  endpoint.

## Version matrix

| Desktop app | Server API 4 (production today) | Server API 6 (v1.4.0) |
| --- | --- | --- |
| **1.2.0** (installed on your PC) | Today's setup. | **Works.** Tested with a 1.2.0 build from its exact source (`3d46b11`) against the upgraded server on production-era data. Sign-in, history, images and files, sending, profiles, DMs, preferences and status all work. The server sent every new event type and 1.2.0 ignored them: 0 errors, 0 failed requests. 1.2.0 users don't get the new features (table below). |
| **1.4.0** (rc.1) | **Works.** Tested against a server built from production's exact commit. Sign-in is by username, and all eight Server Settings sections load. Features that need API 6 are hidden or kept on the PC, and only API 4 endpoints are used. | **Full feature set.** Tested locally. Real voice, soundboard audio between people and multiple PCs over the internet are **not verified yet**. |

Evidence: the readiness report, items D1–D4.

Recommended order: upgrade the server first, then hand out the new app. Both orders are safe; this
one simply avoids a period where new-app users see features "waiting for the server".

## Features and what they need

"Hidden" means the control doesn't appear. "This PC only" means it works but isn't saved to the
account.

### Built in Milestone 13 (v1.3.0-rc.1, never deployed): part of the v1.4.0 server

| Feature | Needs the v1.4.0 server? | Server setting (in `.env`) | Default after the upgrade |
| --- | --- | --- | --- |
| Email sign-up, verification, sign-in by email, password reset by email | **Yes** | `MAIL_TRANSPORT=smtp` + `SMTP_*` + `MAIL_FROM`; `REGISTRATION_MODE` | **Off**: invite-only, no email. Sign-in stays by username. |
| Server icon, description, default notifications, channel layout editor, voice user limits | **Yes** | none | On (hidden on API 4) |
| Member timeouts (Moderate Members permission) | **Yes** | none | On. Owner, Administrator and Moderator **gain the permission by default**; Members don't. Roles you customized keep exactly their stored permissions. |
| GIF picker | **Yes** | `GIF_PROVIDER=giphy` + `GIF_API_KEY` | **Off** |
| Large files (up to 5 GB, resumable; >500 MB expire after 24 h) | **Yes** | `UPLOAD_LARGE_FILES=true` (+ limits) | **Off**. Normal attachments work as before. |
| Unread tracking fix (a never-opened channel counts as read up to its start) | **Yes** | none | On. Existing unread counts didn't change in the rehearsal. |
| Drafts, quick switcher (Ctrl+K), emoji picker, message actions, UI scale, density, sounds and keybind settings, voice panel, Daily Word | No (app only) | none | — |

### Milestone 14.5 (preview `1.4.5-m14.5-preview`): webcams and the camera overlay

Details and the camera checklist are in [milestone-14.5-face-to-face.md](milestone-14.5-face-to-face.md).

| Feature | Needs the upgraded server? | 1.4.5 app on API 4 (or a 1.4.0-rc.1 server) | 1.2.0 / 1.4.0 app on a camera-enabled server |
| --- | --- | --- | --- |
| Webcams in voice, call view, camera strip under streams | **Yes**: the server must grant the camera source (`camera: true` in `/api/meta`, this branch). No database migration. | The camera button is disabled and explains that the server needs the update | They never receive camera tracks (their subscription policy has refused cameras since Milestone 5) and can't send one. Voice, streams and chat with 1.4.5 users are unaffected. |
| Camera overlay over games | Same as webcams (it only shows cameras) | Can be arranged; stays empty | — |
| "Stream" permission renamed **Video** (camera + screen share) | Label only | Shown as Video | Shown as Stream |

The camera grant follows the existing Stream permission. After the server update, everyone who
can screen share can also turn on a camera, unless a role or channel denies it.

## Mixed versions in the same server or call

- **Messages, DMs, files, reactions, pins, profiles (name, bio, avatar), presence, voice and
  screen sharing** work between 1.2.0 and 1.4.0 users on either server.
- **Soundboard:** only 1.4.0 users in the call hear clips. Ask everyone to update before relying on
  it.
- **Cameras (Milestone 14.5):** only 1.4.5 users see and send them, and only on a server with the
  camera grant. Other users in the same call notice nothing.
- **Profile styles and animated images:** 1.4.0 users see them; 1.2.0 users see the plain profile.
  Avatars and banners may move continuously for them.
- **Timeouts:** enforced by the server for everyone. A timed-out 1.2.0 user should see a generic
  "can't send" error instead of the 1.4.0 timeout notice (expected from the API; not tested).

## After a rollback to the old server (R1)

Nothing is deleted. The database keeps migrations 6–12, which the old server ignores.

- Profile styles, synced themes, soundboard clips, saved messages and notes stay stored but are
  unavailable until the server is upgraded again.
- 1.4.0 apps fall back as in the API 4 column above: the theme is kept on the PC and the other
  features are hidden.
- 1.2.0 apps work as before.

The rollback and the roll-forward were rehearsed: the old server opened the migrated database,
passed `verify` and completed 20/20 write operations.
